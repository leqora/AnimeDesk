# v0.13.2 AniList zahtevi u grupama — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Concurrent AniList lookups (`getForTitle`) are merged into one request per wave (`id_in` for ids, aliased searches for titles), a `Remaining: 0` pause no longer holds data that already arrived, and the user sees one toast when AniList rate-limits.

**Architecture:** Query strings move to `src/main/anilistQueries.js`. `anilist.js` splits `gql` into an unqueued `request` + `enqueue`, tags errors with `status`/`graphql`, moves the `Remaining: 0` sleep onto the queue, and reports pauses via a throttled `onRateLimited`. A new `src/main/anilistBatch.js` collects `byId`/`search` calls in a 40 ms window and, when its queue task runs, sends at most one id request and one search request. `getForTitle` uses the batcher. `index.js` forwards the rate-limit callback as an event; preload exposes it; a small `RateLimitNotice` in `App.jsx` shows a toast.

**Tech Stack:** Electron main (ESM `.js`, package NOT `"type": "module"`), React renderer, vitest (+ `renderUi`/`makeFakeApi` from `tests/unit/ui/helpers.jsx`).

**Spec:** `docs/superpowers/specs/2026-10-19-v0.13.2-anilist-batching-design.md` (numbered points A1…D22 are referenced below). Read it.

## Global Constraints

- Window `windowMs = 40` (`batchWindowMs` option on `createAniList`), `maxSearches = 10`, `maxIds = 50`; ids request `Page(perPage: 50) { media(id_in: $ids, type: ANIME) { FIELDS } }`; each search alias `Page(perPage: 10) { media(search: $sN, type: ANIME) { FIELDS } }`. Search text ONLY through GraphQL variables.
- One member of a kind → the old single query (`BY_ID` / `SEARCH`), unchanged request shape.
- Rate-limit callback only for pauses ≥ 3000 ms, never for the final 429, at most once per 30 000 ms (measured with the injected `now`).
- `SEARCH_VERSION` stays `2`. `search()`, `candidates()`, `refreshAiring`, `relations`, `viewer`/`listEntry`/`saveProgress`, `poster()` keep their behavior (they only inherit the queue-pause change).
- Copy (single braces): `toast.anilistRateLimited` sr „AniList privremeno ograničava zahteve — slike i podaci stižu za oko {seconds} s”, en „AniList is limiting requests for a moment — posters and info will arrive in about {seconds} s”. Toast icon `'alert'`.
- Event channel `EVENTS.anilistRateLimited = 'event:anilist-rate-limited'`, payload `{ seconds: Math.ceil(waitMs / 1000), until }`.
- No episode data anywhere (spoiler rule untouched).
- Every commit ends with exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (this project rule beats any default model trailer). Never `git add -f`; never commit `.superpowers/`.
- TDD: failing test first. Existing tests must not be weakened; if you change an existing assertion say which and why in your report.
- Many files are CRLF; prefer the Edit tool over sed.

## Review Focus

1. A wave where every search returns 400 forever (complexity limit lowered) must terminate with a bounded number of requests and reject only the members — test in Task 2 (`request` always 400 → all rejected, calls ≤ 2·n).
2. A search text containing `"`, `\`, `$`, `{`, `}` or a newline must never break the query or another member's result — test in Task 2.
3. Two titles whose candidates share one exact search text in the same wave get the same result and both cache files are written — test in Task 3.
4. A rate-limit pause while 25 search results are waiting → after the pause they go out in ≤ 3 requests, not 25 — test in Task 2 (members collected while the queue is blocked).
5. A toast event arriving while the window is hidden (tray) or after `until` → no toast later — test in Task 4.
