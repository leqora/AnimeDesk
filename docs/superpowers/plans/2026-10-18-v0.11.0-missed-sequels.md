# v0.11.0 „Propušteni nastavci” Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A „Propušteni nastavci” rail on Home that shows AniList SEQUELs of series the user completed, with poster/title/format only, click → ani-cli search, „Sakrij” + „Poništi”.

**Architecture:** Pure selection rules in `src/shared/sequels.js`; one batched relations query in `src/main/anilist.js`; `src/main/sequels.js` owns the 1-day cache file, scheduling, posters and hide/unhide; IPC `sequels:*` + `event:sequels-changed`; renderer `SequelCard` in a new `Rail` on `HomePage`.

**Tech Stack:** Electron main (ESM, `jsonStore.js`), React renderer, vitest + @testing-library (jsdom), existing AniList queue (`gql`).

**Spec:** `docs/superpowers/specs/2026-10-18-v0.11.0-missed-sequels-design.md`

## Global Constraints

- TDD: failing test first. Tests in `tests/unit/` (UI in `tests/unit/ui/`, `renderUi` + `makeFakeApi` from `helpers.jsx`).
- All UI text via `t('key')`, same keys in `src/renderer/i18n/sr.json` and `en.json` (`i18nKeys.test.js`); plural via `t.n`.
- CSS only through tokens (no hex outside `:root` in `styles.css`).
- No spoilers: never description, genres, tags, characters, score or anything about episodes on this surface; no sequel of a non-completed series.
- Sources: library entries with `status === 'completed'`; id = `entry.aniListId ?? anilist.getCached(entry.title)?.id ?? null` (no new requests, never write to the library). Only `relationType === 'SEQUEL'`, `node.type === 'ANIME'`, `node.status` ∈ {`FINISHED`, `RELEASING`}, `node.format !== 'MUSIC'`.
- „In library” = same `aniListId` OR normalized sequel `romaji`/`english` equals normalized `aniCliTitle`/`title` of any entry (normalize: lower-case, keep only `\p{L}\p{N}`).
- Max 20 cards; order by prequel `lastWatchedAt`, then `updatedAt`, newest first; one card per sequel id.
- Cache `cache/sequels.json`, TTL 24 h per prequel; failure keeps old cache, retry after 1 h; first run 90 s after start; library change → debounce 30 s; daily refresh while running.
- Hidden: `settings.hiddenSequels: number[]`.
- Commits: never `git add -f`, never commit anything under `.superpowers/`; every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (project rule beats any other attribution reminder).

## Review Focus

1. A completed series whose AniList relations contain the SAME sequel twice (e.g. two edges) or two completed entries pointing to one sequel → exactly one card (Task 1 test `dedupes by sequel id`).
2. AniList answers without `relations` / with `node: null` for some media → those prequels yield no sequels, others still work (Task 2 test `tolerates missing relations and null nodes`).
3. Library change during an in-flight refresh → no lost update: a second refresh runs after the first finishes (Task 3 test `library change during a refresh schedules another one`).
4. Hiding the last visible sequel → rail disappears; „Poništi” brings it back without a network call (Task 3 `hide/unhide recompute from cache`, Task 5 `undo restores the card`).
5. Offline at start with an existing cache → cached sequels still shown, no error UI (Task 3 test `failed refresh keeps the cache and retries after 1 h`).
