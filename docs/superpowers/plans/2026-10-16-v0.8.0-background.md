# v0.8.0 Background & Notifications Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AnimeDesk keeps running in the tray, starts with Windows on request, allows one instance, and notifies (Windows toast + in-app bell) when a new episode of a "watching" series airs and when a download finishes or fails while the window is not focused.

**Architecture:** Testable main modules with injected dependencies (`settings` keys, `anilist.refreshAiring`, `notificationsStore`, `airingWatcher`, `background` helpers, `downloads.onFinished`); `src/main/index.js` only wires Electron (`Tray`, `Notification`, `powerMonitor`, single-instance lock, login item). Renderer: bell + panel (`Modal`) in the sidebar, a new settings section, `event:open-anime` / `event:open-page` handling in `App.jsx`.

**Tech Stack:** Electron, React 19, vitest + Testing Library, Playwright `_electron` for e2e/manual.

**Spec:** `docs/superpowers/specs/2026-10-16-v0.8.0-background-design.md`

## Global Constraints

- Notification/bell text: only the series title and the episode number — never an episode title, description or thumbnail (spoilers). No new surface shows episode title/image/description (those would have to go through `src/main/seriesEpisodes.js`).
- Copy (sr / en), verbatim: new episode title „Nova epizoda” / "New episode", body `<series> — EP N`; download „Preuzeto: <series> — EP N” / "Downloaded: <series> — EP N", „Preuzimanje nije uspelo: <series> — EP N” / "Download failed: <series> — EP N"; tray hint „AnimeDesk radi u pozadini — ikona je pored sata” / "AnimeDesk keeps running in the background — the icon is next to the clock"; tray menu „Otvori AnimeDesk” / "Open AnimeDesk", „Izađi” / "Quit"; bell panel title „Obaveštenja” / "Notifications", button „Označi sve kao pročitano” / "Mark all as read".
- Settings defaults: `closeToTray: true`, `launchAtLogin: false`, `notifyNewEpisodes: true`, `notifyDownloads: true`, `trayHintShown: false`.
- `appUserModelId` = `com.leqora.animedesk`. Login item args `['--hidden']`, only when `app.isPackaged`.
- Airing: only library entries with `status === 'watching'` and a numeric `aniListId`; batch ≤ 50 ids per AniList request; batch at start (+60 s), every 6 h, on `powerMonitor` `resume`, and `AIRED_GRACE_MS` after an episode of a series aired; next-airing timer looks at most 6 h ahead; notify only episodes > remembered and aired within the last 24 h; first sighting of a series seeds without notifying; several skipped → one notification for the highest.
- Bell: max 30 stored items (newest first), unread badge shows "9+" above 9; only new-episode items.
- No change to existing behavior when `closeToTray` is off (close quits).
- All existing tests (1020) keep passing; `npm run test:e2e` passes.
- Many files are CRLF — edit with the Edit tool. Commit trailer exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. First run after updating with several "watching" airing series already past their episodes → zero notifications (seeded). (Task 4 test.)
2. App off for 3 days, started → no notification for episodes older than 24 h; one per series for the newest within 24 h. (Task 4 test.)
3. AniList down during batch → timer still fires from the last known `airingAt`; no crash, no tight retry loop. (Task 4 test.)
4. Quit from tray / `quitAndInstall` while `closeToTray` is on → the window's close handler does not cancel the quit. (Task 5 test on the close decision.)
5. Download cancelled or paused → no OS notification; error → "failed" notification. (Task 5 test.)

### Task 2: AniList batch airing refresh

**Files:** Modify `src/main/anilist.js`; Test `tests/unit/anilist.test.js`

**Interfaces — Produces:** `anilist.refreshAiring(ids: number[]) -> Promise<Map<number, { status, episodes, nextAiring }>>`. Query: `query ($ids: [Int], $page: Int) { Page(page: $page, perPage: 50) { media(id_in: $ids, type: ANIME) { id status episodes nextAiringEpisode { episode airingAt } } } }`, chunks of 50 ids through the existing `gql` queue. For each returned id whose cache file `cacheFile(cacheKey(null, id))` exists and is not `notFound`, merge `status`, `episodes`, `nextAiring` (via `toNextAiring`), `fetchedAt: now()` and write it back (keep poster etc.). Ids without a cache file are returned in the map but not written. A failed chunk rejects the whole call (caller handles).
  The watcher reads entries with the existing `anilist.getCached(null, { aniListId: id })` (no new getter).

- [ ] Step 1: tests — one request for ≤50 ids, two for 51; merge keeps `poster`/`title`, updates `nextAiring` (seconds → ms) and `fetchedAt`; missing cache file not created; HTTP error rejects; `getCached(null, { aniListId })` returns the merged entry.

### Task 4: Airing watcher

**Files:** Create `src/main/airingWatcher.js`; Test `tests/unit/airingWatcher.test.js`

**Interfaces:**
- Consumes: `anilist.refreshAiring(ids)` (Task 2), `anilist.getCached(null, { aniListId })`; `library.list()`; `AIRED_GRACE_MS`, `airedCount` from `src/shared/airing.js`.
- Produces:
  - pure `dueNotifications({ entries, infoById, notified, now }) -> { due: [{ animeId, aniListId, title, episode }], notified }` — `entries` filtered to `watching` + numeric `aniListId`; `aired = airedCount(info, now)`; unseen id → seed `notified[id] = aired ?? 0`, no due; `aired > notified[id]` and that episode's `airingAt` (`info.nextAiring.airingAt` when `now >= airingAt`) is within 24 h → due one item with `episode = aired`, `notified[id] = aired`; aired but older than 24 h → just update `notified[id]`. Title = library entry `title`.
  - `createAiringWatcher({ library, anilist, file, notify, now = Date.now, setTimeout, clearTimeout, setInterval, clearInterval })` → `{ start(), refresh() -> Promise, check(), stop() }`. `start`: `refresh` after 60 s, every 6 h; `check` on start and on a timer at the earliest future `airingAt` among watched series (≤ 6 h ahead, else 6 h); after a due episode schedule `refresh` in `AIRED_GRACE_MS`. `refresh` failures are logged and swallowed (no retry loop; next scheduled run retries). `notified` persisted to `file` (JSON `{ [aniListId]: episode }`). `notify(item)` is called per due item.
- [ ] Step 1: tests (fake timers, fake anilist/library): seeding (Review Focus 1); 24 h window (Review Focus 2); multiple skipped → one; non-watching / missing aniListId ignored; refresh rejection → check still fires at known airingAt, no extra refresh calls before the 6 h interval (Review Focus 3); timer re-arms; persistence across instances; `stop()` clears timers.
- [ ] Steps 2–5: FAIL → implement → PASS + full suite → commit `feat(airing): watcher that notifies when a watched episode airs`.
