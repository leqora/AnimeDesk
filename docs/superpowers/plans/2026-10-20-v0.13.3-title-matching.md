# v0.13.3 Pouzdanije uparivanje naslova — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ani-cli titles are matched to AniList by a measured rule (clean query + similarity over all titles/synonyms + threshold) instead of "first result"; a fuzzy (`close`) match is only used for display; ids used for episodes/AniSkip/sequels/airing come only from exact matches or a known id; the manual AniList picker works without login.

**Architecture:** New pure `src/shared/titleMatch.js` (Appendix A of the spec is normative). `anilist.js` uses `searchQueries`/`pickMatch`, tags cache entries with `match`/`matchVersion`, upgrades old exact entries offline and re-searches the rest. Main consumers (`seriesEpisodes`, `skipLookup`, `sequels`) and shared `airing.js` ignore `close` matches for anything id-derived. Renderer: `infoCache`, `useAniListInfo`, `AnimeDetail`, `AniListMatch`.

**Tech Stack:** Electron main (ESM `.js`, package NOT `"type": "module"`), React renderer, vitest (+ `renderUi`/`makeFakeApi` from `tests/unit/ui/helpers.jsx`).

**Spec:** `docs/superpowers/specs/2026-10-20-v0.13.3-title-matching-design.md` (points 1…17 referenced below). Read it, including Appendix A.

## Global Constraints

- Appendix A code is normative: same regexes, constants (0.6, 0.25, GENERIC, ROMAN), Dice definition (bigrams of `loose` strings WITH spaces, multiset), main titles before synonyms for exact, first result wins ties.
- `MATCH_VERSION = 3` in `titleMatch.js`; `SEARCH_VERSION = MATCH_VERSION` in `anilist.js`.
- Cache entry fields: title lookups `match: 'exact' | 'close'`, `matchVersion: SEARCH_VERSION`; id lookups `match: 'id'`. Old entries have no `match`; treat "no `match`" as NOT close everywhere (`match !== 'close'`), except `sequels.getCachedId` which needs `match === 'exact'`.
- No spoilers; no new surface with episode title/image/description; `seriesEpisodes.js` stays the only gate for episode data.
- New copy: `anilist.uncertain` sr „Nije sigurno koja je ovo serija na AniList-u.”, en „Not sure which AniList series this is.”
- Every commit ends with exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never `git add -f`; never commit `.superpowers/`.
- TDD: failing test first. Existing tests must not be weakened; report each changed assertion with the spec point that changes the behavior.
- Many files are CRLF; prefer the Edit tool over sed.

## Review Focus

1. All 68 fixture cases pass and the extra unit tests pin the branches the fixture does not decide (exactTok, cleaned title in `score`, ties, Dice spacing).
2. An old wrong title entry (no `matchVersion`) must never come back after a complete search with no hit; an incomplete search (network/429) must keep it without writing; current-version stale entries keep today's fallback (existing test).
3. Offline upgrade of old exact entries makes no network request.
4. A `close` match never: writes `aniListId`/`totalEpisodes`, feeds ani.zip/filler/AniSkip/sequels/airing badges, or lands under an `id:` key in the renderer cache.
5. Picker without login: match card and picker visible; sync line/opt-out and `anilistSync.stateFor` only when connected.
