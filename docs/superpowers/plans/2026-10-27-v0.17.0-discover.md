# v0.17.0 „Otkrij” + rok za AniList prijavu — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** New „Otkrij” page (current season, next season, popular movies, trending; genre filter; „Iznenadi me”) fed by one AniList request only while the page is open, plus a 5 s cap on waiting for the saved AniList login at startup.

**Architecture:** Pure rules in `src/shared/discover.js` (reusing `isLaterPart`/`isSideStory`/`FORMATS` from `shared/recommendations.js` and `libraryMatch` from `shared/schedule.js`); `anilist.discover()` = one aliased query; service `src/main/discover.js` copies the `src/main/schedule.js` pattern (cache file, 12 h TTL, 1 h pause, force ≤ 1/min, posters on demand with a 4-download limiter); renderer `DiscoverPage.jsx` copies the `SchedulePage.jsx` state/retry/focus pattern and reuses `Rail` (moved out of `HomePage.jsx`) and `RecommendationCard`.

**Tech Stack:** Electron 45, React, vitest + Testing Library, lucide-react.

**Spec:** `docs/superpowers/specs/2026-10-27-v0.17.0-discover-design.md` (point numbers below = spec points). Read it before your task.

## Review Focus

1. Library entry that is a later part (e.g. „Season 2”) → still shown with poster and „U Watchlist-i”, click opens detail (Task 1 `buildRails` test + Task 4 UI test).
2. `NOT_YET_RELEASED` item in the season/movies rail (not only „Uskoro”) → not a button, „Počinje: …” (Task 4 test).
3. Genre selected, then data refresh removes that genre → behaves as „Svi žanrovi”, no empty page (Task 4 test).
4. „Iznenadi me” with an empty pool (genre with only upcoming items) → `aria-disabled`, focus stays on the button, no navigation (Task 4 test).
5. Season boundary while the page stays open or cache from previous season → refetch, rail titles follow the record's season (Task 3 test).
