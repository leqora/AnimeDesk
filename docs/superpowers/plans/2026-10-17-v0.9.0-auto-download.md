# v0.9.0 Auto-download Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-series switch that downloads newly aired episodes by itself, with "waiting for source" retries in the download queue.

**Architecture:** Pure candidate/retry logic in `src/shared/autoDownload.js`; the per-series switch + boundary `after` lives in `series-prefs.json` via `seriesPrefs.js`; a main-process `autoDownloader.js` reads the AniList cache (kept fresh by `airingWatcher`) and hands episodes to the existing `downloads.enqueue` with `auto: true`; `downloads.js` gains a `waiting` status with timed retries for auto items. UI: a checkbox in `AnimeDetail.jsx`, `waiting`/"Auto" rendering in `DownloadsPage.jsx`.

**Tech Stack:** Electron main (ESM via electron-vite), React renderer, vitest + Testing Library (`renderUi`/`makeFakeApi` in `tests/unit/ui/helpers.jsx`).

**Spec:** `docs/superpowers/specs/2026-10-17-v0.9.0-auto-download-design.md`

## Review Focus

1. Episode boundary never re-hands an episode: after `enqueue`, `after` moves to the highest handed episode even if the enqueue skipped it (already downloaded / already queued) — test in Task 4.
2. Restart with `waiting` items: they stay `waiting` (not `paused`), keep `retryAt`, and a past `retryAt` re-queues right after load — test in Task 3.
3. Switch turned on for a series whose next episode airs in the future → nothing downloads now; after `airingAt + 20 min` exactly that one episode is handed — test in Task 4.
4. `downloadDir` cleared while auto series exist → `check()` hands nothing and does not move `after` — test in Task 4.
5. Toggling quality/sub-dub/subtitle offset/spoiler reveal on a series must keep `autoDownload` (and vice versa) — test in Task 2.

### Task 1: Pure auto-download logic

**Interfaces:**
- Consumes: `airedCount(info, now)` from `src/shared/airing.js`.
- Produces:
  - `SOURCE_LAG_MS`, `MAX_PER_CHECK = 3`, `GIVE_UP_MS = 3 * 24 * 3600 * 1000`, `RETRYABLE_ERRORS` (array of the 4 codes).
  - `maxWatched(entry) → number` (0 when none; integers only).
  - `initialAfter({ entry, info, now }) → number` = `max(airedCount ?? 0, maxWatched(entry))`.
  - `autoDownloadCandidates({ entries, prefsFor, infoById, now, max = MAX_PER_CHECK }) → [{ animeId, aniCliTitle, episodes: number[] }]` where `prefsFor(aniCliTitle) → { after } | null` and `infoById` is keyed by `aniListId`.
  - `nextCheckAt({ entries, prefsFor, infoById, now }) → number | null` — earliest `nextAiring.airingAt + SOURCE_LAG_MS` that is `> now`, over eligible series (on, watching, aniListId, aniCliTitle); `null` if none.
  - `retryDelayMs(attempts) → number` (attempts = failures so far, ≥ 1): 1→30 min, 2→1 h, 3→2 h, 4→4 h, ≥5→6 h.
  - `shouldGiveUp({ firstTriedAt, now }) → boolean` = `now - firstTriedAt >= GIVE_UP_MS`.
