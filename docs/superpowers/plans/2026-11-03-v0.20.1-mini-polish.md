### Task 2: Search session bookkeeping (SearchPage)

Three deferred cases in `src/renderer/pages/SearchPage.jsx`:
(a) **Reset during `pickAnime`:** `pickAnime` awaits `seriesPrefs.get`; a Home→Home reset (`resetSeq`) in that window is undone when the await resolves (`restartFor` starts a new list / `answerMenu` answers). Fix: `pickAnime` remembers `live.current.resetCount` (new counter bumped by the reset effect) and does nothing after the await if it changed (it still cancels nothing — the reset already cancelled the list).
(b) **Reset cancels a play start:** while a „Nastavi” start (`pendingWatch` with `episode`) is busy, Home→Home adds it to `abandoned`, so the episode never opens. Fix: `start()` records `live.current.pendingPlay = params.episode != null`; the reset effect leaves a busy start alone when `pendingPlay` is true (no `abandoned`, no state change).
(c) **Superseded start leaks a session:** when start A has not replied and start B begins, A's reply hits `seq !== l.startSeq` and returns, leaving A's ani-cli session waiting on its menu forever. Fix: in that branch, if `r?.sessionId` and it is not `l.playingSession` → `l.ignore.add(sid); api.watch.cancel(sid)`.

**Files:**
- Modify: `src/renderer/pages/SearchPage.jsx`
- Test: `tests/unit/ui/SearchPage.test.jsx`

- [ ] **Step 1: failing tests** (one per case, using the fake api's deferred `watch.start` / `seriesPrefs.get`):
  - `reset while a picked series reads its prefs keeps the page reset`: menu kind `anime` → click a result (prefs promise pending) → bump `resetSeq` → resolve prefs `{ quality: '720' }` → `watch.start` called only once (the initial search), no menu shown, `answerMenu` not called.
  - `Home reset does not cancel a busy Continue start`: `pendingWatch {query, anime, episode:'5'}` → before `start` resolves bump `resetSeq` → resolve `{ sessionId:'s1' }` → `watch.cancel` not called; then `onPlaying({sessionId:'s1'})` → text `search.playing` shown.
  - `a superseded start cancels its session when it replies`: search „a” (start pending) → search „b” → resolve first with `{ sessionId:'old' }` → `watch.cancel('old')`; a later `onMenu({ sessionId:'old' })` shows nothing.
- [ ] **Step 2:** `npx vitest run tests/unit/ui/SearchPage.test.jsx` → new tests FAIL.
- [ ] **Step 3:** implement (a)–(c) as described; keep all existing comments' intent.
- [ ] **Step 4:** `npx vitest run tests/unit/ui/SearchPage*.test.jsx` and `npm test` → PASS.
- [ ] **Step 5: commit** `fix(search): keep resets, play starts and superseded starts consistent`.
