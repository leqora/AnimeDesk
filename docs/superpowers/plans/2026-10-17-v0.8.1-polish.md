# v0.8.1 Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the fullscreen-after-tray bug found in the live check of 0.8.0 and the small follow-ups left from v0.8.0, and make `npm run release` stop failing on flaky tests.

**Architecture:** Main-process fixes in `fullscreen.js`, `airingWatcher.js` and `index.js`; one renderer fix in `NotificationBell` (closed by a prop from `App` through `Sidebar`); test-infrastructure fixes in `vitest.config.mjs` and `App.test.jsx`.

**Tech Stack:** Electron, React, vitest 5 (jsdom for UI tests).

**Spec:** no spec document (small change); design approved in chat 2026-10-17, copied here:
1. Hiding the window to the tray must not save `fullscreen: false`. When the window is shown again (tray, second instance, notification click) it returns to fullscreen if the setting is still on. Leaving fullscreen with Esc/F11 still saves as before. Decision: what is remembered is the user's choice, not the window state at hide time.
2. When a check from cache finds a "new episode", `airingWatcher` first runs `refresh()` and notifies only if the episode still counts as aired on the fresh AniList data (a delayed episode no longer gives a false "new episode"). Decision: if the refresh fails (offline), notify from cache as today.
3. The bell panel closes when the player starts.
4. `second-instance` is registered right after the single-instance lock; a second launch during a slow start shows the window as soon as it exists.
5. `npm run release` must not fail on the flaky `App.test.jsx` "Esc listener once" test (count only App's own listener) or on vitest "Timeout waiting for worker" (find the cause first, then limit workers).

Out of scope: Action Center click (`ToastActivatorCLSID`), HKCU Run entry on uninstall, the rest of "v0.8.0 — svesno ostavljeno".

## Review Focus

1. User left fullscreen with Esc, then closed to the tray → after showing again the window is NOT fullscreen and `settings.fullscreen` stays `false` (Task 1 test).
2. Window hidden while not fullscreen → showing it never enters fullscreen (Task 1 test).
3. Refresh fails (offline) → the cached "new episode" is announced exactly once, and no refresh loop starts (Task 2 test).
4. Fresh data moves the episode later (delayed) → no notification now; the check timer is re-armed to the new `airingAt`, and the episode is announced once when it really airs (Task 2 test).
5. `stop()` while the confirming refresh is in flight → nothing is announced afterwards (Task 2 test).

### Task 2: Confirm a new episode with fresh data before announcing it

**Files:**
- Modify: `src/main/airingWatcher.js`
- Test: `tests/unit/airingWatcher.test.js`

**Interfaces:**
- Consumes: `anilist.refreshAiring(ids): Promise` (exists), `dueNotifications(...)` (unchanged, pure).
- Produces: `refresh(): Promise<boolean>` — `true` when fresh data was applied and checked, `false` when the refresh failed or the watcher is stopped. `check({ fresh = false } = {})` keeps its signature.

Behaviour to implement (the plan decides this; tests below pin it):
- A check with `fresh: false` that finds `due.length > 0` does NOT announce and does NOT persist the advanced memory; it starts `refresh()` (shared in-flight promise) and returns.
- `refresh()` → `check({ fresh: true })` announces whatever is still due on fresh data (today's code path).
- If `refresh()` resolves `false` and the watcher is not stopped, run one cache check that announces (internal option, e.g. `check({ confirmed: true })`); it must not start another refresh.
- Fresh checks (`fresh: true`) announce directly, as today.

- [ ] **Step 1: Write the failing tests** (use the file's existing fake library/anilist/timers helpers; read them first):
  - `it('refreshes before announcing an episode found in cache')`: notified `{1: fr(5, T)}`, cache `info(6, T - MIN)` (aired), `refreshAiring` resolves and the cache stays the same → `refreshAiring` called once, then `notify` called once with episode 6; `notify` not called before the refresh resolves.
  - `it('does not announce a delayed episode and re-arms for the new time')` (Review Focus 4): timer check at `airingAt`; `refreshAiring` rewrites the cache to `info(6, T + 2 * H)` → no `notify`; advancing timers by `2 * H` → one `notify` with episode 6 (after its own confirming refresh).
  - `it('announces from cache once when the refresh fails')` (Review Focus 3): `refreshAiring` rejects → exactly one `notify` (episode 6); `refreshAiring` called exactly once; advancing timers by `MIN` adds no calls.
  - `it('announces nothing when stopped during the confirming refresh')` (Review Focus 5): `stop()` before `refreshAiring` resolves → no `notify`, also when it rejects.
  - `it('confirms several due series with one refresh')`: two series due from cache → one `refreshAiring` call with both ids, two notifications.
  - Update existing timer-path tests that expected an immediate `notify` from a cache check so they let the confirming refresh resolve; do not weaken their assertions.
