# v0.15.0 Raspored — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new "Raspored" page shows the episodes airing in the next 7 local days ("Moje serije" from the library, "Sve" from AniList `airingSchedules`), with only the episode number and time, and no poster for later seasons/side stories of series outside the library.

**Architecture:** Pure rules in new `src/shared/schedule.js` (poster/visibility rules reuse `src/shared/recommendations.js`, checked on the 125-case fixture). `anilist.js` gets `schedule(fromMs, toMs)` (pages of 50 through the existing queue). New main service `src/main/schedule.js` (cache file, lazy refresh only from `list()`, 1 h failure pause, posters on demand). IPC `schedule:*`. Renderer: new `SchedulePage` + menu item + route.

**Tech Stack:** Electron main (ESM `.js`, package NOT `"type": "module"`), React renderer, vitest (+ `renderUi`/`makeFakeApi` from `tests/unit/ui/helpers.jsx`).

**Spec:** `docs/superpowers/specs/2026-10-20-v0.15.0-schedule-design.md` (points 1…26 referenced below). Read it.

## Global Constraints

- Fixture `tests/fixtures/schedule.cases.json` is normative and must not be edited: `posterAllowed(c) === c.expected.poster` and `shownInAll(c) === c.expected.shown` for all 125 cases. `posterAllowed` = `isAdult !== true && !isLaterPart(c) && !isSideStory(c)` using the functions from `src/shared/recommendations.js` (import, never copy). `shownInAll` = `isAdult !== true && format !== 'MUSIC'`.
- Window: 7 local days from today's local midnight (calendar arithmetic, DST-safe; 2026-10-25 is the Europe switch to winter time).
- AniList: `SCHEDULE` query text exactly as spec point 7, variables only; ≤ 8 pages of 50; `airingAt_greater = floor(from/1000) − 1`, `airingAt_lesser = ceil(to/1000)`; through the existing `gql` queue; never `anilistBatch.js`, never `cache/anilist`.
- Service timings: refresh only from `list()` (never at start, never by timer); TTL 6 h (`21_600_000`) or new local day; failure pause 1 h (`3_600_000`), `failedAt` in the future = now; `force` bypasses the pause at most once per 60 s (`60_000`); posters ≤ 40 ids per call, ≤ 4 downloads at once, 8 s timeout each.
- Ids from the AniList title cache only when `match === 'exact'`; `dropped` entries are never library matches.
- No spoilers: only episode number(s) and air time; never a series description, episode title/image/description, tags, characters. Episode data never appears here, so nothing goes through `seriesEpisodes.js` (say so in the module comment of `src/main/schedule.js`). A later part/side story outside the library: poster never downloaded or shown; posters render only through `PosterFrame info={{ poster }}`, never `Poster title=…`.

## Review Focus

1. Page open across local midnight: the day row shifts, a selected day that left the window falls back to „Danas”, `list()` is called again — test in Task 5.
2. 2026-10-25 (DST end) inside the window: 7 distinct days, an episode at 23:30 local on the 25th lands on the 25th — test in Task 1.
3. Library entry linked only by a `close` title-cache match: not a library match by id, and its cached poster is never used for a later-part item — tests in Task 1 (`libraryMatch`) and Task 3 (`posters`).
4. „Pokušaj ponovo” clicked repeatedly: second `force` within 60 s makes no request; after a failure the next non-force `list()` within 1 h makes none — test in Task 3.
5. „Obriši keš” while a refresh is in flight: the late result is discarded, file stays deleted — test in Task 3.
