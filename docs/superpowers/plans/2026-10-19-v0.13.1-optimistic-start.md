# v0.13.1 Optimistično pokretanje — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At app start the health light turns green immediately when the last successful ani-cli self-test is under 72 h old with the same `bash`/`ani-cli` versions; the real check finishes in the background, and tool updates never run while an ani-cli session is alive.

**Architecture:** A pure rule (`src/shared/health.js`) decides whether to trust the stored record; a tiny store (`src/main/healthStore.js`) reads/writes `health.json`; `aniCliBridge` counts live sessions; `healthCheck.js` gets `run({ optimistic })`, the record write/clear, and a wait-until-idle before every `updateAll`; `index.js` wires it. No renderer change.

**Tech Stack:** Electron main (ESM `.js`, package is NOT `"type": "module"`), vitest.

**Spec:** `docs/superpowers/specs/2026-10-19-v0.13.1-optimistic-start-design.md` (read it; numbered points are referenced as A1…E17).

## Global Constraints

- Trust window: `HEALTH_MAX_AGE_MS = 72 * 60 * 60 * 1000`; trusted only when `0 <= now - okAt < HEALTH_MAX_AGE_MS`.
- Fingerprint tools: `HEALTH_TOOLS = ['bash', 'ani-cli']`; `null` versions compare equal to `null`.
- Record shape on disk: `{ okAt: <ISO string>, tools: { bash: <string|null>, 'ani-cli': <string|null> } }` in `paths.health` = `<userData>/health.json`.
- Busy poll interval: `BUSY_POLL_MS = 5000`, no upper limit.
- `optimistic` only for the startup call in `index.js`; `health:recheck`, tool install/update IPC and the 6 h retry stay normal.
- Every commit ends with exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (this project rule beats any default model trailer). Never `git add -f`; never commit `.superpowers/`.
- TDD: failing test first. Existing tests must not be weakened (if you change an existing assertion, say so in your report and why).
- Many files are CRLF; prefer the Edit tool over sed for edits.

## Review Focus

1. A check that tested the old ani-cli while `tools:check-updates` swapped it must not write the new version (versions read before the self-test) — test in Task 3.
2. Background self-test fails while a download/watch session runs → stays `updating`, `updateAll` not called until idle — test in Task 3.
3. `dailyUpdate` right after an optimistic start while the user is watching → waits for idle — test in Task 3.
4. Corrupt or unreadable `health.json` (EPERM, garbage) → treated as no record, no crash — test in Task 1.
5. A session whose `done` rejects (or whose `runImpl` throws synchronously after the counter went up) must not leave the counter stuck above 0 — test in Task 2.

### Task 3: Optimistic run, record write/clear, wait-for-idle updates, wiring

**Files:**
- Modify: `src/main/healthCheck.js`, `src/main/index.js` (around lines 241 and 315)
- Test: `tests/unit/healthCheck.test.js`

**Interfaces:**
- Consumes: Task 1 (`HEALTH_TOOLS`, `toolFingerprint`, `trustLastCheck`, `createHealthStore`, `paths.health`), Task 2 (`aniCli.activeSessions()`).
- Produces: `createHealthCheck({ toolManager, aniCli, isOnline, onState, store = NOOP_STORE, now = () => Date.now(), isBusy = () => false, sleep = (ms) => new Promise(r => setTimeout(r, ms)) })` → `{ run({ optimistic = false } = {}), get(), dailyUpdate({ enabled, now }) }`. Optimistic first state: `{ light: 'green', reason: 'ok', pending: true }` (`healthState('ok', { pending: true })`); every other state has no `pending`. `toolManager.version` may be missing (treat as `() => null`).

Flow (spec C9): missing tools → `missing-tools` (no store access, no network) → if `optimistic && trustLastCheck(...)` emit ok+pending, else emit `checking` → `isOnline` false → `offline` (record untouched) → read fingerprint → self-test ok → `ok` + `store.write({ okAt: new Date(now()).toISOString(), tools })` → else `updating` → wait while `isBusy()` (poll `sleep(BUSY_POLL_MS)`) → `updateAll(AUTO_UPDATE_TOOLS)` → if updated, read fingerprint again, self-test → ok + write; otherwise `source-down` + `store.clear()`. Store errors are caught with `console.warn` and never change the state. `dailyUpdate` waits the same way before its `updateAll` (after `markUpdateCheck`).
