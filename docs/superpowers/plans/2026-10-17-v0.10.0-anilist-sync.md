# v0.10.0 AniList prijava + slanje progresa — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect an AniList account with a pasted PIN token (stored only via `safeStorage`) and push watched-episode progress — forward only, only for series whose AniList match the user confirmed.

**Architecture:** Pure decisions (local progress, forward-only rule, status, retry schedule, JWT expiry) live in `src/shared/anilistSync.js`. Main owns everything that touches the token: `src/main/anilistAuth.js` (encrypted token file) and `src/main/anilistSync.js` (reconcile-on-library-change scheduler with a persisted queue), both using authenticated calls added to the existing request queue in `src/main/anilist.js`. The renderer only sees `{ connected, name, expiresAt, state }` and per-series sync state.

**Tech Stack:** Electron (main: `safeStorage`, `shell`, `powerMonitor`), React renderer, vitest + jsdom (`renderUi`, `makeFakeApi`), AniList GraphQL `https://graphql.anilist.co`.

**Spec:** `docs/superpowers/specs/2026-10-17-v0.10.0-anilist-sync-design.md` — read it before every task; every value below comes from it.

## Global Constraints

- Commits end with exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (project rule beats any session default). Never `git add -f`; never commit anything under `.superpowers/`.
- Code, comments, commit messages in English; UI text only via `t('key')` with identical keys in `src/renderer/i18n/sr.json` and `en.json` (`i18nKeys.test.js`), plurals via `t.n` (`_one/_few/_other`).
- Package is not `"type": "module"` — scripts/configs `.mjs`. Many files are CRLF: use the Edit tool, not scripted rewrites.
- The token never leaves main: not in `settings.json`, logs, `console.*`, IPC results, error messages or the renderer.
- No spoilers: new surfaces show series-level data only (title, year, format, episode count, poster) — never a description, never episode titles/thumbnails. Anything episode-level must go through `src/main/seriesEpisodes.js`.
- Forward only: never send a lower `progress`; never touch an AniList entry that is `COMPLETED`.
- Nothing is sent for an entry without `aniListConfirmed === true`, or with `aniListSync: false` in `series-prefs.json`.
- Renderer CSS: tokens only (no hex outside `:root` in `styles.css`); new buttons get the same hover + `:focus-visible` ring as existing ones.
- TDD: failing test first. Run the whole suite (`npm test`) before each commit; on "Timeout waiting for worker" just rerun.

## Review Focus

1. **Two library entries with the same `aniListId`** — second confirm returns `{ ok:false, error:'taken', title }`; nothing ever merges progress. Test in Task 3.
2. **`aniListId` changed by the auto-fill in `AnimeDetail.jsx` after confirmation** — confirmation drops to `false`, sync for that id stops and its pending item is dropped. Tests in Task 3 and Task 5.
3. **AniList ahead of local (watched elsewhere) or `COMPLETED`** — no mutation, `sent` remembers AniList's values so the read is not repeated on every library change. Tests in Task 1 and Task 5.
4. **Offline / 429 / 5xx, then app restart** — pending item survives in `anilist-sync.json` with its `attempts`/`nextAt`, no burst of requests at start (first run at +60 s). Test in Task 5.
5. **Token rejected mid-queue** — account state `expired`, no further requests, queue kept; a new successful connect clears the queue and state. Tests in Task 4 and Task 5.

### Task 5: Sync scheduler with persisted queue  *(review on Opus — time/state logic)*

**Files:**
- Create: `src/main/anilistSync.js`
- Test: `tests/unit/anilistSyncService.test.js`

**Interfaces:**
- Consumes: Task 1 (`localProgress`, `wantsSync`, `decide`, `retryDelay`, `MAX_REJECTED`, `DEBOUNCE_MS`), Task 2 (`listEntry`, `saveProgress`, `AniListAuthError`), Task 3 (`library.list/get/findConfirmed`, `seriesPrefs.getAniListSync`), Task 4 (`auth.token()`, `auth.markExpired()`, `auth.onChange`).
- Produces: `createAniListSync({ file, library, seriesPrefs, anilist, auth, now, setTimeout, clearTimeout })` returning:
  - `check()` — reconcile: for every eligible entry (`aniListConfirmed`, `aniListId`, `getAniListSync(aniCliTitle ?? title)` true) with `wantsSync(entry, sent[id])`, (re)schedule that id at `now + DEBOUNCE_MS` (a newer change moves the deadline); drop pending items whose entry is no longer eligible.
  - `syncNow(entryId)` — same but due immediately (used right after confirm).
  - `start()` — load file, first run at +60 s; `resume()` — run due/backoff items now; `stop()` — clear timers, no further requests.
  - `stateFor(entryId) -> { state: 'off' | 'synced' | 'pending' | 'error' | 'mismatch' | 'expired', progress?: number, retryAt?: number }`.
  - `onChange(fn) -> unsubscribe` (fires when any state changes; index.js turns it into an event).
  - `reset()` — clears `sent` + `pending` + file (used by disconnect and by a new connect).
- Behaviour per item run (one at a time, token from `auth.token()`; no token → stop running, keep queue): `listEntry` → `decide` → `send` → `saveProgress` then `sent[id] = { progress, status, at }`; `skip` → `sent[id] = remember`; `mismatch` → state `mismatch`, item dropped (re-evaluated on next local change). Failures: `AniListAuthError` → `auth.markExpired()`, keep item, stop; network/5xx/429 → `attempts++`, `nextAt = now + retryDelay(attempts)`; other rejections count separately and after `MAX_REJECTED` → state `error`, item dropped until local progress changes. Persist after every change with `writeJsonAtomic` (shape from the spec, section 6).

  - unconfirmed entry / `aniListSync` false / missing `aniListId` → no calls.
  - AniList ahead → no `saveProgress`; a following `check()` with unchanged library makes **no** `listEntry` call.
  - `COMPLETED` remote → no save, state `synced` (remembered).
  - mismatch (episodes 12, local 13) → no save, `stateFor` = `mismatch`.
  - network error → retries at +1 min, +5, +15, +60, then +6 h (assert `listEntry` call times).
  - pending item survives a restart: new service on the same file, `start()` → nothing before +60 s, then the call.
  - auth error → `markExpired` called once, no further calls even after time passes, item still in file; after `auth.onChange` with a token again + `reset()` the queue is empty.
  - entry's `aniListId` changed (confirmed → false) between schedule and run → no request, item dropped.
  - `stop()` → no request after the debounce elapses.
  - `syncNow` → request without waiting 30 s.
  - a request in flight while `check()` schedules the same id again → no parallel second request for that id; it runs after the first finishes.
