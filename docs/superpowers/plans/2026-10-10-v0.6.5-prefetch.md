# v0.6.5 Prefetch of the next episode — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From ~80 % of an episode in the in-app player, prepare the ani-cli session for the next episode in the background and park it where ani-cli launches the player, so "Next" starts almost instantly.

**Architecture:** All logic lives in `src/main/watchService.js`. A prefetch is a normal `spawn()` session with a `quiet` flag (no UI events, gives up on menus that need the user) and a `gate` promise its `onPlay` awaits. `watch()` adopts a matching quiet session (same player title, episode, quality, mode) by opening the gate and returning its `sessionId`; otherwise it kills it and spawns as today. The renderer does not change.

**Tech Stack:** Electron main process (Node, ESM), vitest.

**Spec:** `docs/superpowers/specs/2026-10-10-v0.6.5-prefetch-design.md` (read it before starting any task).

## Global Constraints

- ani-cli stays original: only the existing bridge (`ANI_CLI_PLAYER`) and env vars; no changes to the ani-cli script.
- Prefetch only for ani-cli sessions played in the **in-app player** (`settings.playerMode === 'internal'` and `internalPlayer.play` actually used). Never for external mpv, the mpv fallback, the in-app→mpv switch (`reason: 'external'`) or `playLocal`.
- `PREFETCH_AT_PERCENT = 80`, `PREFETCH_TTL_MS = 10 * 60 * 1000`, at most one prefetch session at a time.
- Next episode number = `nextEpisodeNumber(info.episode, 1)` from `src/shared/player.js` (the same function `App.jsx` uses), as a string.
- Match key: `{ forTitle: info.title, episode, quality, mode }`; `watch()` compares `anime === forTitle`, `String(episode) === episode`, and the resolved `params.quality` / `params.mode`.
- While `quiet`: no `EVENTS.menu`, `EVENTS.playing`, `EVENTS.sessionEnd`; a menu that is not auto-answered → `entry.failure = 'needs-user'`, answer `null`.
- Prefetch never changes recording: no `runPlayer`, `celebrations.hold`, `afterPlayback`, `positions` for a parked session; a prefetch error never breaks `onProgress`.
- No renderer, i18n or UI change.
- Code, comments and commit messages in English; every commit ends with exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; git identity `leqora <dzonzi777@gmail.com>` (`git -c user.name=leqora -c user.email=dzonzi777@gmail.com commit …`). Work on branch `feat/v0.6.5-prefetch`; never push, merge or release.
- Fakes in tests must follow the real contract: `onPlay` blocks until the player ends; `internalPlayer.closed` reports the snapshot through `onProgress` before resolving; `session.kill()` eventually resolves `done`.
- If this plan does not match the file you open (names, lines, behavior), stop and report NEEDS_CONTEXT instead of guessing.

## Review Focus

1. User presses "Next" seconds after crossing 80 %, before ani-cli reached `onPlay` → the quiet session is adopted and plays as soon as it parks; it must not be killed and re-spawned (Task 2 test "adopts a prefetch that has not parked yet").
2. Settings changed between prefetch and "Next" (quality or sub/dub) → no adoption, the stale session is killed, a fresh session starts (Task 2 `it.each` mismatch test).
3. A recovery of the current episode (`recover` → `startRetry`) while a prefetch is parked → the prefetch survives and is not duplicated when the recovered playback crosses 80 % again (Task 1 test "does not duplicate a prefetch with the same key").
4. `startSession` throws for the prefetch (tools vanished) right when the threshold is crossed → the episode is still recorded as watched (Task 1 test "a failing prefetch never breaks recording").
5. App quits or the user backs out and never presses "Next" → no ani-cli process lingers (Task 1 TTL + `dispose` tests, Task 3 `before-quit` wiring).

```js
    current: () => (active ? { playbackId: active.playbackId, title: active.info.title, episode: active.info.episode } : null),

    return playing
```

```js
  // Returns true once this playback has decided (started a prefetch, or found there is nothing to prefetch).
  function maybePrefetch(entry, info, p) {
    if (entry.cancelled || entry.retrying) return false
    if (!((p?.maxPercent ?? 0) >= PREFETCH_AT_PERCENT)) return false
    if (info.episode == null || !Number.isFinite(Number(info.episode))) return true
    if (isLastEpisode(info.episode, getTotalEpisodes(info.title))) return true
    const params = { ...retryParams(entry, info), episode: String(nextEpisodeNumber(info.episode, 1)) }
    const key = { forTitle: info.title, episode: params.episode, quality: params.quality, mode: params.mode }
    if (prefetch && sameKey(prefetch.prefetchKey, key)) return true
    discardPrefetch()
    const next = spawn(params, null, { quiet: true })
    next.prefetchKey = key
    prefetch = next
    prefetchTimer = setTimer(discardPrefetch, PREFETCH_TTL_MS)
    return true
  }

  function discardPrefetch() {
    clearTimer(prefetchTimer)
    prefetchTimer = null
    const entry = prefetch
    if (!entry) return
    prefetch = null
    entry.cancelled = true
    entry.gate.open(false)
    entry.session.kill()
  }
```
