# v0.12.0 — Watchlist: pretraga, brojači, žanrovi + Podaci (rezervna kopija) (design)

Datum: 2026-10-19. Grana: `feat/v0.12.0-watchlist-data`. P2 po `docs/seanime-analysis/04-plan.md` (red „watchlist filteri/pretraga + sekcija Podaci”). Korisnik je u chatu dobio konkretan predlog (A1–A4, B1–B4) i **odobrio ga u celosti, uključujući automatsku dnevnu kopiju** (`docs/STATUS.md` → „SLEDEĆE (od 2026-10-19 posle 0.11.1)” tačka 0). Ono što je bilo u predlogu piše se bez oznake; detalji koje je kontrolor dodao pri pisanju speca označeni su **(odluka)**.

## Zašto

Watchlist danas ima samo padajući meni statusa i sortiranje. Sa 40+ serija korisnik ne može brzo da nađe seriju, ne vidi koliko čega ima i ne može da filtrira po žanru. Takođe, svi podaci (biblioteka, dnevnik gledanja, pozicije, postavke po seriji, podešavanja) žive samo u `%APPDATA%\AnimeDesk` — nema načina da se naprave rezervne kopije, prenesu na drugi računar ili vrate posle greške. Posle ovog izdanja Watchlist se pretražuje i filtrira za sekundu, a Podešavanja imaju odeljak „Podaci” sa izvozom, uvozom i automatskom dnevnom kopijom.

#### Format fajla rezervne kopije **(odluka)**

```json
{
  "app": "AnimeDesk",
  "kind": "backup",
  "format": 1,
  "appVersion": "0.12.0",
  "createdAt": "2026-10-19T10:00:00.000Z",
  "data": {
    "library":     { "version": 1, "anime": { "<id>": { …unos… } } },
    "watchlog":    { "version": 1, "entries": [ … ] },
    "seriesPrefs": { "version": 1, "series": { … } },
    "positions":   { "version": 1, "items": { … } },
    "settings":    { … }
  }
}
```

- `data.*` su tačno sadržaji fajlova `library.json`, `watchlog.json`, `series-prefs.json`, `positions.json` kako ih servisi drže u memoriji (izvoz čita iz servisa, ne sa diska, da ne bi izvezao neupisano stanje) — dodaju se metode `snapshot()` (duboka kopija baze) u `library.js`, `watchLog.js`, `seriesPrefs.js`, `positions.js`.
- `settings`: sanitizovana podešavanja (`sanitizeSettings` oblik, bez `systemName`/`isPackaged` koje dodaje `get()`), **bez** polja vezanih za ovu instalaciju: `lastSeenVersion`, `trayHintShown`, `fullscreen` **(odluka)**.
- **AniList token se nikad ne izvozi**: `anilist-auth.bin` se ne čita; `anilist-sync.json` (red slanja), keševi, `downloads.json`, `notifications.json`, `airing-notified.json`, `profile.json`, `episode-lists.json`, `tools/` se ne izvoze **(odluka)**. Test: izvoz pri povezanom nalogu (lažan `aniListAuth` sa tokenom `"SECRET-TOKEN"`) ne sadrži taj niz nigde u JSON-u, a `dataBackup` ne dobija `aniListAuth` uopšte kao zavisnost.
- Upis: `writeJsonAtomic` (tmp + rename), JSON sa uvlačenjem 2.

#### Uvoz — provera

Main (`dataBackup.readBackup(file)`):
- Fajl veći od **(odluka)** 50 MB → greška `too-large` (bez čitanja). Nije JSON → `invalid`. `app !== 'AnimeDesk'` ili `kind !== 'backup'` → `invalid`. `format > 1` → `newer` („Kopija je iz novije verzije AnimeDesk-a”). `data.library.anime` nije objekat → `invalid`.
- **Biblioteka — ista validacija kao `library.js`:** **(odluka)** iz `library.js` se izvlači čista funkcija `sanitizeEntry(raw)` koja koristi postojeći `validatePatch` + proveru ostalih polja: `id` neprazan string (= ključ u `anime`), `title` neprazan, `status` iz `STATUSES`, `rating` 1–10 ili `null`, `totalEpisodes` pozitivan ceo ili `null`, `watchedEpisodes` niz brojeva (`uniqSorted`), `episodeNotes` objekat sa string vrednostima (ključevi = brojevi kao string; ostalo se odbacuje), `comment` string (nedostaje → `''`; postojeća obrada iz `validatePatch`), `aniCliTitle` string ili `null`, `aniListId` pozitivan ceo ili `null`, `aniListConfirmed` boolean, `addedAt`/`updatedAt` ISO string (nedostaje → vreme uvoza), `lastWatchedAt`/`pinnedAt` ISO string ili `null`; nepoznata polja se odbacuju. Neispravan unos (baca) → **preskače se** i broji kao `skipped`. Posle pojedinačne provere, na celoj listi: duplikat po normalizovanom `aniCliTitle ?? title` → zadržava se prvi, ostali `skipped`; isti potvrđen `aniListId` kod više unosa → prvi ostaje potvrđen, ostali `aniListConfirmed: false`; više od `MAX_PINNED` zakačenih → najstariji `pinnedAt` ostaju, ostali `pinnedAt: null`.
- `watchlog.entries`: zadržavaju se samo zapisi sa `animeId` koji postoji u prihvaćenoj biblioteci, `episode` konačan broj, `at` string, `id` string (nedostaje → novi uuid), `source` string; sortirano po `at`.
- `seriesPrefs`, `positions`: **(ispravka posle builder check-a)** servisi pri učitavanju proveravaju samo da je `series`/`items` objekat, a pojedinačne zapise čiste tek lenjo u `get`/`forSeries`. Zato `replaceAll` dobija prave sanitizere po zapisu: za `seriesPrefs` — ključ = normalizovan naslov (neprazan), `quality`/`mode` iz `QUALITIES`/`MODES`, `subOffset` preko `readOffsets` (zapisuju se samo ≠ 0), `reveal` preko `readReveal`, `metaOff === true`, `autoDownload` preko `readAuto`, `aniListSync === false`; isti oblik koji piše `persist` (prazan zapis se izostavlja). Za `positions` — ključ oblika `<naslov>#<epizoda>`, `position`/`duration` konačni, `duration > 0`, `at` konačan broj; ostalo se odbacuje. Nije objekat → prazno.
- `settings`: `sanitizeSettings` (nepoznato/loše se vraća na podrazumevano); polja `lastSeenVersion`, `trayHintShown`, `fullscreen` uvek ostaju trenutna. **(odluka)** `downloadDir` se uvozi samo ako folder postoji na ovom računaru, inače ostaje trenutni.
- Biblioteka posle provere ima 0 unosa, a fajl je imao > 0 → greška `invalid` (ne zameniti punu biblioteku praznom zbog loših podataka). Fajl sa izričito praznom bibliotekom (0 unosa) je dozvoljen, uz pregled „0 serija”.
- Pregled koji ide u renderer (`{ token, createdAt, appVersion, series, logEntries, skipped, current: { series, logEntries } }`): bez naslova i bez ikakvih podataka iz fajla osim brojeva i datuma. Proveren sadržaj se drži u memoriji main-a pod `token` (jedan u isto vreme; novi `pick` zamenjuje stari; **(odluka)** važi 10 minuta), da „Zameni podatke” ne čita fajl ponovo i ne može da primi podatke iz renderera.

2. **Kopija pre uvoza:** trenutni podaci (isti format kao izvoz, iz `snapshot()` servisa) → `backups/pre-import-YYYY-MM-DDTHH-mm-ss.json` **(odluka: u folderu `backups`, ne u korenu; ne broji se u 7 dnevnih, čuva se poslednjih 5 `pre-import-*`)**. #### Automatska dnevna kopija **(odluka za detalje)**

- Fajl `backups/auto-YYYY-MM-DD.json` (lokalni datum), isti format kao izvoz.
- Raspored u `dataBackup.js` (čist deo — izbor imena, da li treba kopija, šta obrisati — u `src/shared/backupRules.js`, testiran): prva provera **2 min** posle starta, pa tajmer do sledeće lokalne ponoći + 5 min (najviše 6 h pa ponovo provera), i na `powerMonitor` `resume`. Provera: ako za današnji lokalni datum već postoji `auto-<danas>.json` → ništa. Inače upis, pa brisanje starijih `auto-*.json` tako da ostane **7 najnovijih po datumu u imenu** (ne po vremenu izmene fajla; fajlovi koji ne odgovaraju obrascu se nikad ne brišu).
- Sat vraćen unazad: ime za „danas” možda već postoji → ništa; nikad se ne briše kopija sa datumom u budućnosti samo zato što je „novija” — brisanje je samo po sortiranju imena, a 7 najnovijih po imenu se uvek zadržava (prihvaćeno: kopija sa budućim datumom može da zauzme mesto dok je ne istisne 7 novijih).
- Prazni podaci (0 serija i 0 zapisa dnevnika) → kopija se ne pravi (nova instalacija ne istiskuje dobre kopije praznim).
- Biblioteka je pri startu bila oštećena (`library.wasCorrupt`) → dnevna kopija se taj dan ne pravi (da ne istisne poslednje dobre kopije); dobre kopije ostaju.
- Neuspeh upisa → `console.warn`, sledeći pokušaj na sledećoj provori (tajmer/resume); ne prikazuje se korisniku.
- `stop()` na `before-quit` gasi tajmere. Nema uključivanja/isključivanja u UI (odobreno kao uvek uključeno). **(odluka)** U odeljku „Podaci” sitan red „Poslednja automatska kopija: 19. 10. 2026.” (ili „još nije napravljena”) + dugme „Otvori folder podataka” pokriva pristup kopijama.

Posle brisanja: `airingWatcher.refresh()` pa `autoDownloader.check()` i `sequels.check()` (raspored emitovanja i id-evi po naslovu se ponovo pune). #### IPC i preload (**(odluka)** imena)

`INVOKE.dataExport` `data:export` → `{ ok: true } | { ok: false, canceled: true } | { ok: false, error }`; `INVOKE.dataImportPick` `data:import-pick` → `{ ok: true, preview } | { ok: false, canceled: true } | { ok: false, error: 'invalid'|'newer'|'too-large'|'read-failed' }`; `INVOKE.dataImportApply` `data:import-apply` (token) → vidi gore; `INVOKE.dataInfo` `data:info` → `{ cacheBytes, lastAutoBackup: 'YYYY-MM-DD' | null }`; `INVOKE.dataClearCache` `data:clear-cache` → `{ cacheBytes }`; `INVOKE.dataOpenFolder` `data:open-folder`; `INVOKE.libraryFacets` `library:facets`. Preload: `window.animedesk.data.{ export, importPick, importApply, info, clearCache, openFolder }`, `library.facets()`. Nijedan odgovor ne sadrži token ni sadržaj `anilist-auth.bin`.

## Ne-ciljevi

- Sinhronizacija/kopija u oblaku, šifrovanje kopije, spajanje (merge) uvoza sa postojećim podacima — uvoz uvek **zamenjuje**.
- Uvoz AniList liste ili MAL izvoza.
- Izbor koliko dnevnih kopija se čuva, isključivanje dnevne kopije, vraćanje dnevne kopije iz UI liste (korisnik je uvozi kao bilo koji fajl preko „Uvezi”).
- Izvoz preuzetih fajlova, dnevnika preuzimanja, obaveštenja, keševa, alata.
- Pretraga po opisu, likovima, tagovima, studiju; više žanrova odjednom; filter po godini/formatu.
- Novi AniList zahtevi zbog žanrova/romaji naslova.

## Anti-ciljevi (neuspeh čak i ako „radi”)

- AniList token (ili bilo šta iz `anilist-auth.bin`) u fajlu kopije, u IPC odgovoru, logu ili rendereru.
- Uvoz koji pola podataka zameni, a pola ne (mora rollback), ili koji zameni punu biblioteku praznom zbog lošeg fajla.
- Lažni „Novi nivo!”, „Serija završena”, obaveštenja o novim epizodama ili auto-preuzimanja pokrenuta samim uvozom zbog promene id-eva (auto-preuzimanje po uvezenim postavkama je u redu — to su korisnikove postavke).
- Dnevna kopija koja istisne dobre kopije praznim/oštećenim podacima, ili petlja tajmera.
- Pretraga koja „ne nađe” seriju zbog dijakritika ili velikih slova; prečica `/` koja krade kucanje u drugim poljima.
- Bilo kakav spojler: na Watchlist-i nema ničeg o epizodama osim onog što kartica već prikazuje.

## Ograničenja

- Pravila projekta (`CLAUDE.md`): TDD, svi tekstovi preko `t()` sa istim ključevima u `sr.json`/`en.json` (množina `t.n`), CSS samo tokeni, paket nije `"type": "module"`, ani-cli netaknut.
- Main ne veruje rendereru: token za uvoz, putanje biraju samo sistemski dijalozi u main-u; renderer nikad ne šalje putanju ni sadržaj.
- Postojeći testovi Watchlist-e (`sortItems`, padajući meni statusa) se menjaju svesno; nijedna postojeća provera ne sme da se oslabi bez razloga u izveštaju.
- Windows: `writeJsonAtomic` (rename) — fajl kopije se piše tako i u `backups/`.
