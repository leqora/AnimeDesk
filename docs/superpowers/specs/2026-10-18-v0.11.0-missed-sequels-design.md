# v0.11.0 — „Propušteni nastavci” (design)

Datum: 2026-10-18. Grana: `feat/v0.11.0-missed-sequels`. P2 po `docs/seanime-analysis/04-plan.md` (red „Propušteni nastavci” šina) i `03-oblast-ostali-featurei.md` §4 tačka 1. Korisnik je dobio konkretan predlog u chatu (4 tačke: kada se prikazuje, šta se vidi, radnje, podaci) i nastavio bez ispravki („idemo dalje posle” uz objavu 0.10.1). Ono što je bilo u predlogu piše se bez oznake; detalji koje je kontrolor dodao pri pisanju speca označeni su **(odluka)**.

## Zašto

Kad korisnik završi seriju, često ne zna da postoji nastavak (nova sezona, film) ili zaboravi na njega. AnimeDesk već zna koje su serije završene i njihov `aniListId`; AniList zna relacije. Posle ovog izdanja Početna sama pokaže „Propušteni nastavci” — samo za ono što je korisnik stvarno završio, bez ijednog detalja priče.

## Ciljevi

1. **Kada se nastavak prikazuje.**
   - Izvor: unosi biblioteke sa `status === 'completed'` i poznatim AniList id-em. **Odluka korisnika (posle builder check-a, opcija A):** uzima se svaki prepoznat id — potvrđen (`aniListConfirmed`) ili automatski pogođen. `aniListId` se danas upisuje u biblioteku samo kad se otvori detalj serije (`AnimeDetail.jsx`, nepotvrđeno pogađanje po naslovu); kad ga unos nema, id se uzima iz postojećeg AniList keša po naslovu (`anilist.getCached(entry.title)` — kartice i posteri ga već pune), **bez novih zahteva i bez upisa u biblioteku**. Nema id-a ni u kešu → unos se preskače. Prihvaćen rizik: pogrešno pogođen id (npr. S1 prepoznata kao S2) može da ponudi pogrešan nastavak — prikazuju se samo poster i naslov, a „Sakrij” ga trajno uklanja. Unosi „Pauzirano”/„Gledam”/„Planiram”/„Odustao” se **ne** uzimaju (poster nastavka može da bude spojler za nešto što korisnik nije završio).
   - Za svaki takav unos uzimaju se AniList relacije sa `relationType === 'SEQUEL'` i `node.type === 'ANIME'` (ne „side story”, „spin-off”, „alternative”…).
   - Nastavak ulazi u šinu samo ako je `status` `FINISHED` ili `RELEASING`. `NOT_YET_RELEASED`, `CANCELLED`, `HIATUS` → ne.
   - **(odluka)** Format `MUSIC` se preskače; sve ostalo (TV, TV_SHORT, MOVIE, OVA, ONA, SPECIAL) ulazi.
   - Nastavak se ne prikazuje ako je već u biblioteci (bilo koji status), ili ako ga je korisnik sakrio. „U biblioteci” = **(odluka, iz builder check-a)** isti `aniListId` **ili** isti naslov: normalizovan `romaji`/`english` nastavka (mala slova, samo slova i cifre — kao `norm` u `anilist.js`) jednak normalizovanom `aniCliTitle` ili `title` nekog unosa. Tako ne iskače sezona koju korisnik već gleda/planira a čiji detalj nije otvarao.
   - **(odluka)** Isti nastavak od dve završene serije (npr. dva unosa iste serije) prikazuje se jednom. Lanci se ne prate unapred: S3 se pojavi tek kad je S2 u biblioteci i završena (prirodno sledi iz pravila iznad).
   - **(odluka)** Redosled: po tome kada je prethodnik poslednji put gledan (`lastWatchedAt`, pa `updatedAt`), najnoviji prvi; najviše 20 kartica.
2. **Šta se vidi.**
   - Šina „Propušteni nastavci” na Početnoj, ispod „Nastavi gledanje” (isti `Rail` obrazac, strelice kad ima više nego što staje). Nema nastavaka → nema šine (ni naslova).
   - Kartica: poster, naslov nastavka, red sa formatom · godinom · brojem epizoda (npr. „TV · 2017 · 12 ep.”; nepoznato se izostavlja), **(odluka)** i sitnije „Posle: <naslov prethodnika iz biblioteke>” da se zna zašto je tu (naslov serije koju je korisnik završio — nije spojler). **(odluka)** `RELEASING` dobija malu oznaku „Emituje se”.
   - **Nikad opis, žanrovi, tagovi, likovi, ocena ni bilo šta o epizodama.** Ova površina ne prikazuje naslove/slike/opise epizoda, pa ne ide kroz `src/main/seriesEpisodes.js`; ako se ikad doda bilo šta o epizodama nastavka, mora kroz njega.
   - **(odluka)** Naslov: `title.english ?? title.romaji` (kao `toInfo`).
3. **Radnje.**
   - Klik na karticu (ili Enter/Space na njoj) pokreće ani-cli pretragu sa naslovom nastavka — isti tok kao kad korisnik upiše naslov u polje za pretragu na Početnoj i pritisne Enter (`watch.start({ query })`), polje za pretragu pokazuje taj tekst. **(odluka)** Upit je `romaji` (ani-cli naslovi u biblioteci su romaji, npr. „Shingeki no Kyojin”), a ako ga nema — `english`.
   - Dugme **„Sakrij”** (ikona ×, `aria-label` „Sakrij <naslov>”), vidljivo na hover i na fokus (kao ▶/★ na `MediaCard`), trajno uklanja taj nastavak sa šine. **(odluka)** Posle sakrivanja toast „Sakriveno: <naslov>” sa „Poništi” (postojeći `ToastProvider`, 6 s, Ctrl+Z).
   - Obe radnje rade tastaturom (pravi Tab, `:focus-visible` prsten).
4. **Podaci.**
   - Novi batch upit u `src/main/anilist.js` kroz postojeći red zahteva (`gql`): `Page(page: 1, perPage: 50) { media(id_in: $ids, type: ANIME) { id relations { edges { relationType node { id type format status seasonYear episodes title { romaji english } coverImage { large } } } } } }`, po 50 id-eva po zahtevu (kao `refreshAiring`).
   - Keš 1 dan po prethodniku: **(odluka)** fajl `cache/sequels.json` (`{ version: 1, byId: { [prequelId]: { at, sequels: [ { id, title, romaji, format, status, year, episodes, coverUrl } ] } } }`); upituju se samo id-evi kojih nema ili su stariji od 24 h. Neuspeo zahtev ne briše postojeći keš; ponovni pokušaj tek posle 1 h **(odluka)**.
   - Posteri: data-URL kroz main (isti put kao postojeći posteri — renderer CSP ne dozvoljava spoljne slike), **(odluka)** samo za nastavke koji stvarno ulaze u šinu (ne za sve relacije), keširani uz zapis (ne preuzimaju se ponovo dok se `coverUrl` ne promeni).
   - Kada: **(odluka)** prvi put 90 s posle starta (posle batch AniList osvežavanja na +60 s), posle promene biblioteke (debounce 30 s — isti put kao `airingWatcher`/`anilistSync`), i jednom dnevno dok aplikacija radi. Renderer dobija listu IPC-om pri otvaranju Početne i događajem kad se lista promeni.
   - **(odluka)** Sakriveni nastavci: `settings.hiddenSequels: number[]` (AniList id-evi nastavaka), menja ih samo main akcija `sequels:hide` / `sequels:unhide`.
   - Offline / AniList ne radi: prikazuje se ono što je u kešu; prazan keš → nema šine, bez poruke o grešci.

## Ne-ciljevi

- Najavljeni nastavci (`NOT_YET_RELEASED`) sa datumom — moguće kasnije.
- Prequel/side story/spin-off preporuke, Discover, trending, preporuke po žanru.
- Dodavanje nastavka u Watchlist direktno sa kartice (unos traži ani-cli naslov; ide kroz pretragu kao i sve ostalo).
- Spisak sakrivenih nastavaka u Podešavanjima (vraćanje je samo „Poništi” odmah posle sakrivanja) — moguće kasnije.
- Sinhronizacija sa AniList nalogom korisnika (koristi se samo javni upit, bez tokena).

## Anti-ciljevi (neuspeh i ako „radi”)

- Bilo kakav spojler: opis, likovi, naslovi epizoda, ili nastavak serije koju korisnik nije završio.
- Dodatno opterećenje AniList-a koje izazove 429 i uspori postere ostatka aplikacije (najviše jedan batch zahtev po 50 završenih serija po osvežavanju + posteri samo za prikazane nastavke).
- Šina koja „gnjavi”: sakriven nastavak se ne vraća sam.

## Ograničenja

- Pravila projekta: TDD, svi tekstovi preko `t()` (sr + en, isti ključevi), CSS samo kroz tokene, `Modal`/toast obrasci postojećih komponenti, nikad `git add -f`, nikad `.superpowers/` u commit-u, commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- AniList ~30 zahteva/min, jedan red zahteva za celu aplikaciju (`anilist.js` `gql`).
- Keš AniList podataka serije (`cache/anilist`) prepisuje `airingWatcher`/`refreshAiring`; nova logika ga ne koristi za relacije (relacije su u svom fajlu).
